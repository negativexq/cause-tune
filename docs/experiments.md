# Experiment record

This document records the verified sequence of CauseTune experiments. Historical experiment IDs remain M3–M6.

## M3 — QLoRA smoke pipeline

M3 established the end-to-end mechanics: QLoRA model construction, a backward pass, assistant-only supervision, adapter saving, and adapter save/reload verification. It used a deterministic smoke dataset and is not comparable to the realistic M4 benchmark.

## M4 — realistic synthetic benchmark

M4 built a 3,000-example structured customer-support intent dataset with separate train, validation, ID, HARD, and OOD splits. The canonical taxonomy and ambiguity rules became the source of truth for validation. Leakage checks found zero exact or normalized cross-split duplicates and no OOD template-family leakage.

The frozen Qwen/Qwen3-4B NF4 baseline scored 88.0% validation, 83.6% ID, 76.8% HARD, and 79.6% OOD accuracy. The evaluation contract was made explicit and fingerprinted so later model comparisons use the same interface.

## M5 — first realistic QLoRA run

M5 trained once on the 2,000-example train split with the initial QLoRA configuration. The run used `shuffle=False` and inherited the manifest order: 10 intents × 200 contiguous examples. With microbatch 1 and accumulation 8, all 250 optimizer windows were single-class. The final 25 optimizer steps were entirely `wrong_item`.

Despite training loss falling from about 0.9109 to 0.000328, semantic accuracy collapsed to 26.8% validation, 24.8% ID, 23.6% HARD, and 20.0% OOD. JSON/schema compliance remained near 100%, showing that formatting was not the desired gain.

## M5 audit

The audit correlated the collapse with class-contiguous order and terminal-class recency. It also checked the training/evaluation chat contracts, decoded supervised labels, optimizer settings, and adapter reload metadata. The evidence ranked unshuffled class blocks and catastrophic recency as the primary supported cause.

## M6 — deterministic shuffle causal test

M6 changed exactly one training-affecting variable: it used a reproducible seed-42 shuffled order. The dataset, labels, model, quantization, LoRA configuration, optimizer settings, masking, and frozen evaluation contract stayed fixed.

All 250 optimizer windows were mixed-class, with no terminal `wrong_item` block. The fresh reloaded adapter reached 99.2% validation, 97.2% ID, 96.0% HARD, and 92.0% OOD accuracy. The result strongly supports training order as the cause of the M5 catastrophic recency failure, while not proving that one seed or one checkpoint is universally optimal.

## Evidence policy

Failed runs remain evidence. The concise files in `results/` summarize persisted artifacts; large adapters and raw telemetry remain local under ignored `outputs/` paths and are not regenerated by release preparation.
